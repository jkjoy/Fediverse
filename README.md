# Fediverse for Typecho

Fediverse 是面向 Typecho 1.3.0 的多作者 ActivityPub 插件。每位 Typecho 作者都可以拥有独立的联邦账号、RSA 密钥、收件箱、发件箱、关注者和正在关注集合，并通过文章、回复、点赞与转发参与联邦宇宙。

当前版本：`0.7.0`。完整版本记录见 [CHANGELOG.md](CHANGELOG.md)。

## 功能概览

### 作者身份

- 通过 WebFinger 发现 `@author@example.com`。
- 为每位作者提供独立的 ActivityPub `Person` Actor 和 2048 位 RSA 密钥。
- 支持昵称、简介、头像、Banner 和最多 4 组 Mastodon 兼容资料字段。
- 作者保存资料后向现有关注者发送签名的 `Update Person`，促使远端刷新缓存。
- 提供 `followers`、`following`、`inbox`、`outbox` 和共享收件箱。

### 发布与互动

- 将公开、无密码的 Typecho 文章作为 `Article` 发布，并携带附件替代文本、标签、已链接的联邦提及和显式内容警告。
- 支持文章 `Create`、`Update`、`Delete` 投递。
- 接收 `Follow`、`Like`、`Announce`、`Create Note` 及对应更新、删除和撤销活动。
- 可在后台查找并关注远端账号，处理 `Accept`、`Reject` 和取消关注。
- 提供按本地作者隔离的后台时间轴，可展开已关注账号的远端转发，显示内容警告、附件链接和标签，并可点赞、转发、回复及撤销互动。
- 后台时间轴标识公开、不列出和仅关注者内容，展示远端投票结果，并提供分页、作者/内容筛选、本地收藏以及按本地作者隔离的静音与屏蔽。
- 在关注解析和入站验签时缓存远端账号昵称、用户名、资料页与头像链接，后台打开页面时不会临时请求远端服务器。
- 提供联邦通知中心，集中显示关注、关注结果、回复、点赞和转发，并区分未读状态。
- 将远端回复接入 Typecho 评论过滤器并写入待审核队列，审核通过后由主题原生评论列表显示。
- 保留远端多级回复的父评论关系，并将已审核的登录用户评论作为联邦回复发送。
- 提供主题可调用的文章互动区，显示点赞、转发、联邦回复数量和最近互动者。

### 运维与安全

- 验证 HTTP Signatures、Digest 和 Date，并通过数据库唯一键原子占用活动 ID，避免并发重复处理。
- 远端请求仅允许 HTTPS，校验公网 DNS 结果并限制响应大小。
- 交互后自动处理少量投递队列，失败任务按指数退避保留并在后续交互时重试；收件箱 HTTPS 重定向时重新签名。
- 同一作者向同一收件箱的任务保持先进先出；早期任务退避时，后续更新和撤销会等待。被阻塞的任务不占用投递批次，自动批次为 1 时其他收件箱也能继续投递。
- 提供按 Actor、来源域的入站速率限制和存储配额。
- 已验签请求在业务处理前写入额度台账；即使目标无效或后续处理失败，也会占用对应额度并留下拒绝状态。
- 远端内容必须明确声明与 Activity Actor 一致的作者；时间轴与评论只接受不早于当前版本的有效 `Update`。
- 非持久状态的入站活动、时间轴和额度台账按保留期清理；有效互动与回复对象关联独立保留。
- 后台支持生成作者身份、同步作者资料、补发最近 20 篇文章、重试或删除队列任务。
- 支持 NodeInfo 2.1，以及 MySQL、MariaDB、PostgreSQL 和 SQLite。

## 运行要求

- Typecho 1.3.0。
- PHP 8.2 或更高版本。
- PHP OpenSSL 和 cURL 扩展。
- 可公开访问的 HTTPS 站点。
- URL 重写将 `/.well-known/*` 和 `/fediverse/*` 交给 Typecho。
- 可选：能定时请求队列地址的 Cron 服务，用于无人访问时继续重试和自动清理。

## 快速安装

1. 将完整的 `Fediverse` 目录放入 Typecho 的 `usr/plugins/`。
2. 在 Typecho 后台启用 **Fediverse**。
3. 打开插件设置，填写联邦域名并检查自动投递、入站限制和队列参数。联邦域名保存前，账号发现和投递不会启动。
4. 每位作者在个人设置的 Fediverse 区域配置账号资料。
5. 配置 Web 服务器重写；低流量站点可额外配置 Cron 保障重试和自动清理。
6. 打开“管理 → 联邦管理”，确认作者身份、数据表和后台菜单已经就绪。

停用插件不会删除数据表或私钥，因此重新启用后联邦身份保持不变。

从旧版本覆盖升级到 `0.7.0` 时，需要在后台停用并重新启用一次插件，以注册新增的评论生命周期钩子；重新启用或打开“联邦管理”也会自动创建通知、本地评论、时间轴元数据、本地限制、收藏、远端账号缓存和远端回复版本表。原有联邦身份、私钥和队列不会被删除。

## 插件设置

### 全局设置

| 设置 | 默认值 | 说明 |
| --- | ---: | --- |
| 联邦功能 | 启用 | 总开关 |
| 联邦域名 | 必填 | 联邦账号的永久身份域名；只填写域名，不含协议、端口或路径，保存后不建议修改 |
| 默认账号简介 | Typecho 简介 | 作者未填写个人简介时使用 |
| 远端回复 | 接收并等待审核 | 可关闭远端回复写入 |
| 单 Actor 每 5 分钟活动上限 | 30 | 填写 `0` 停用 |
| 单来源域每 5 分钟活动上限 | 100 | 填写 `0` 停用 |
| 单 Actor 入站活动存储上限 | 2000 | 统计尚未过期的额度台账；填写 `0` 停用 |
| 单来源域入站活动存储上限 | 10000 | 统计尚未过期的额度台账；填写 `0` 停用 |
| 自动投递 | 开启 | 发布、关注、回复、点赞或收到远端活动后，在请求结束时处理到期队列 |
| 每次自动投递数量 | 1 | 每次交互后最多处理的到期任务数，范围 1 至 10；远端响应较慢时建议保持为 1 |
| Cron 每次处理数量 | 20 | 单次后台处理或 Cron 处理的任务数 |
| 入站活动与时间轴保留天数 | 90 | 有效范围 7 至 3650 天 |
| Cron 令牌 | 随机生成 | 队列处理地址中的私密令牌 |

出现大量 `429` 时，应先确认是否存在异常来源，再按服务器容量调整入站限制；不建议直接关闭所有限制。

### 作者设置

每位作者可以独立设置：

- 是否启用自己的联邦账号。
- 联邦用户名；留空时使用 Typecho 登录名。
- 账号简介。
- 可公开访问的 HTTPS 头像地址。
- 可公开访问的 HTTPS Banner 地址。
- 最多 4 组资料字段名称与内容。

资料字段内容为 HTTPS 地址时会输出为安全的 `rel=me` 链接，其他内容按纯文本转义。联邦用户名只允许字母、数字、下划线和连字符；首次生成身份后不建议修改，否则 Actor URL 会改变。

### 文章联邦元数据

公开文章关联的 Typecho 附件会作为 ActivityPub `Image` 或 `Document` 输出。附件编辑页中的“描述”会作为替代文本；未填写描述时仍会输出附件，但远端无法获得可访问性说明。只有最终公开 URL 为 HTTPS 的附件才会进入联邦对象。

Typecho 标签会输出为结构化 `Hashtag`。正文中已经写成 HTTPS 链接的完整账号，例如 `<a href="https://social.example/@alice">@alice@social.example</a>`，会额外输出为结构化 `Mention`；插件不会在发布请求中为普通 `@user@domain` 文本执行远端 WebFinger 查询。

内容警告使用 Typecho 自定义字段显式控制，插件不会根据标题或正文猜测：

| 自定义字段 | 值 | 作用 |
| --- | --- | --- |
| `fediverse_cw` | 警告文本 | 输出 ActivityPub `summary`，并自动将 `sensitive` 设为 `true` |
| `fediverse_sensitive` | `1`、`true`、`yes` 或 `on` | 在没有警告文本时也将内容标记为敏感 |

在文章编辑页展开“自定义字段”，按上述名称添加即可。远端实例如何折叠 `Article` 取决于其客户端实现。

## Web 服务器

必须确认以下地址由 Typecho 处理，而不是被 Web 服务器直接返回 404：

```text
https://example.com/.well-known/webfinger?resource=acct:author@example.com
https://example.com/.well-known/nodeinfo
https://example.com/fediverse/author/author
```

Nginx 的典型规则：

```nginx
location / {
    try_files $uri $uri/ /index.php?$args;
}
```

Apache 需要启用 `mod_rewrite`，并使用 Typecho 后台生成的伪静态规则。

如果 Typecho 安装在子目录，WebFinger 仍应位于域名根目录。需要在反向代理层将 `/.well-known/webfinger` 和 `/.well-known/nodeinfo` 转发到 Typecho 子目录中的对应路由。

## 自动投递、Cron 与队列

默认启用自动投递。发布或更新文章、关注、点赞、转发、回复以及收到远端活动时，插件会在当前请求结束后处理少量到期任务。失败任务不会丢失，而是按指数退避保留；后续交互会继续尝试。因此有正常访问和互动的小型站点可以不配置 Cron。

Cron 仍适合以下情况：网站长时间没有新访问或联邦活动、关注者分布在较多实例、需要无人值守地持续重试，以及需要自动清理过期活动和时间轴。没有 Cron 时，可在“管理 → 联邦管理”手动处理队列和清理过期内容。

需要 Cron 时，保存令牌并每分钟请求一次：

```text
https://example.com/fediverse/cron/你的Cron令牌
```

Linux Cron 示例：

```cron
* * * * * curl -fsS --max-time 50 'https://example.com/fediverse/cron/替换为令牌' >/dev/null
```

Cron 会处理当前批次的投递任务，并清理超过保留期的普通入站活动、时间轴和额度台账。仍有效或已撤销的点赞、转发记录及远端回复对象关联会继续保留，以维持计数、去重与远端编辑或删除。连续失败 8 次后任务停止自动重试并保留在后台。

Cron 令牌可能出现在服务器访问日志中，应限制日志访问，并尽量在反向代理层限制该路径的来源 IP。

| `0.6.2` | 完整覆盖后打开插件设置，确认“自动投递”已开启。默认每次交互处理 1 条到期任务；Cron 可保留用于无交互期间的重试和自动清理 |
| `0.6.1` | 完整覆盖后打开插件设置；若联邦域名原先留空，必须填写并保存有效域名，联邦功能才会启动。随后可在“管理 → 联邦管理 → 作者账号”复制 Cron 配置 |
| `0.6.0` | 完整覆盖后先打开一次“管理 → 联邦管理”创建远端回复关联表，再运行 Cron 或接收新活动；首次清理前会将仍在日志中的旧回复关联迁入新表 |

| `0.5.0` - `0.5.3` | 完成上述操作；如远端资料或文章曾漏投，可使用“同步作者资料”和“补发最近文章”，然后运行队列 |

`0.6.0` 会新增入站额度台账，并将远端新回复和编辑后的回复恢复为待审核状态，同时接入 Typecho 原生评论过滤器。已有评论状态不会自动改变。

升级到 `0.6.1` 后须先打开插件后台完成建表。已在旧版本清理掉的回复活动无法从日志恢复关联；这些旧评论可保留在 Typecho 中，但之后的远端编辑或删除无法自动匹配。尚存的旧日志会在下次清理时迁移。新增发件箱 `?page=1`、`?page=2` 等页面，可供远端读取较早文章。

`0.6.2` 不新增数据表。升级后请确认插件设置中已保存联邦域名；未设置时插件会保留现有队列，但暂停发现、关注、接收和投递。

`0.6.3` 不新增数据表。自动投递默认开启，本地操作和远端入站活动会在请求结束后处理少量到期任务；已有 Cron 可继续保留作为无人交互期间的重试和清理保障。

`0.7.0` 新增的远端回复版本表会记录回复的最近更新时间，阻止迟到的旧 `Update` 覆盖新正文。升级前已公开的远端副本不会因本地文章改为非公开而自动撤回；此版本会停止返回相应本地评论对象的正文。

升级或更换主题不会自动修改主题模板，文章互动区和联邦回复标记仍需按“主题适配”重新接入。

## 后台入口

### 管理 → 联邦管理

用于运维和诊断：

- 查看作者联邦地址、Actor 状态和密钥生成时间。
- 查看投递队列和已停止重试的任务。
- 查看入站活动及处理状态。
- 立即处理队列、重试或删除任务。
- 批量生成作者身份、同步作者资料、补发最近 20 篇公开文章。
- 清理过期活动。

### 联邦宇宙

顶级菜单包含四个独立页面：

- **通知**：查看关注、关注结果、回复、点赞和转发通知，并一键标记为已读。
- **时间轴**：分页浏览已关注账号投递的新内容，按本地作者、内容/账号或收藏状态筛选，并进行收藏、点赞、转发、回复、静音或屏蔽。
- **关注者**：查看、屏蔽和移除正在关注本站作者的远端账号。
- **正在关注**：查找远端账号、发起关注、查看等待或拒绝状态，并进行静音、屏蔽或取消关注。

所有后台操作都要求管理员权限，并通过 Typecho 安全令牌校验。

## 关注与时间轴

在“联邦宇宙 → 正在关注”中选择本地作者身份，输入完整账号，例如 `@user@example.com`。插件通过 WebFinger 获取远端 Actor，将签名的 `Follow` 放入队列；远端返回 `Accept` 后状态变为“已关注”，返回 `Reject` 后显示“已拒绝”。

本地“等待确认”状态只会在 `Follow` 成功写入投递队列后保留。若队列写入失败，插件会回滚本次关注记录并显示错误，可直接重新发起，不会留下队列为空却长期等待确认的记录。

关注成功后，远端服务器会把公开的 `Note` 或 `Article` 主动投递到本站。插件验签并确认发送者处于关注列表后，将纯文本内容写入对应本地作者的后台时间轴。

时间轴支持：

- 点赞与取消点赞，对应 `Like` 和 `Undo Like`。
- 转发与取消转发，对应 `Announce` 和 `Undo Announce`。
- 发送包含 `inReplyTo` 的公开 `Create Note` 回复。
- 接收已有内容的 `Update` 和 `Delete`。
- 展示 `oneOf` / `anyOf` 投票的选项、票数、截止时间与结束状态。
- 将内容收藏到本站数据库并取消收藏；收藏按接收内容的本地作者隔离，不向远端发送活动。
- 每页显示 20 条，支持按本地作者、正文/Actor 地址和收藏状态组合筛选。
- 使用关注解析或入站验签时保存的远端昵称和资料链接；页面渲染本身不发起远端资料请求。

点赞、转发和回复等出站互动先进入投递队列；本地收藏不进入队列，也不会通知远端。时间轴不会自动公开远端内容，当前也不下载或代理远端附件。

为避免扩大原文可见范围，后台只允许转发和回复明确公开的内容；不列出、仅关注者或无法确认可见性的内容仍可查看和点赞，但不会显示转发与回复控件。

静音和屏蔽都是按本地作者隔离的本地规则。静音后，该账号的新活动不再进入此作者的时间轴、通知或评论；屏蔽在此基础上还会将该账号从此作者的关注者投递扇出中排除。解除限制只影响后续活动，不会自动恢复此前已隐藏的时间轴内容。本站文章本身仍是公开网页，因此本地屏蔽不能阻止对方通过公开 URL 访问文章。

## 文章、回复与互动统计

文章发布时，插件只向当时已经关注该作者的远端收件箱投递。新关注者不会自动收到全部历史文章；需要时可在“管理 → 联邦管理”使用“补发最近文章”。

远端回复只有在以下条件全部满足时才会接收：

- `inReplyTo` 指向本站已发布文章。
- 文章允许评论。
- 收件人匹配文章作者。
- HTTP 签名有效且未超过入站限制。
- Typecho 评论过滤器没有拒绝该回复。

回复内容会转换为纯文本并以 `waiting` 状态写入评论表。文章互动区会统计已接收的待审核回复，但回复正文只有审核通过后才由主题评论列表公开。

远端回复指向另一条已接收评论或本站已联邦评论时，插件会恢复 Typecho 的父评论关系。后台时间轴也会显示被回复对象；父内容已缓存时同时显示摘要。

本地评论满足以下条件时会作为公开 `Note` 发往联邦宇宙：所属文章已发布且未设置密码、评论状态为 `approved`、评论者是已登录的 Typecho 用户，并且该用户已启用联邦账号。文章改为非公开或设置密码后，联邦评论地址不再返回正文；已经投递到远端的副本不会因此自动撤回。评论编辑会发送 `Update`，转为待审核、垃圾评论或被删除时发送 `Delete`。匿名评论没有可验证的 Actor，因此不会冒充文章作者发送；远端评论也不会再次投递，避免形成回环。

评论投递完成入队后才保存联邦发送状态。首次入队或回复对象的账号解析失败时会报告错误，并允许重新审核或编辑评论后重试；失败不会留下阻止重试的“已发送”记录。回复旧评论时，若远端作者已被当前本地账号屏蔽，新建与更新活动不会直接投往该账号；删除活动仍可投递，以清除之前的副本。

Mastodon 的 Favourite 在 ActivityPub 中对应 `Like`，因此文章互动区统一显示为“点赞”，不再单独建立“收藏”统计。后台时间轴的“收藏”是管理员自己的本地书签，与该远端 `Like` 完全独立。

## 主题适配

插件不会全局改写文章正文或评论 HTML。每个主题只需要在文章模板和评论回调中各增加一处调用。

### 显示文章互动区

在文章详情模板 `post.php` 中，将以下代码放在文章正文或标签列表之后、上一篇/下一篇导航或评论区之前。此处 `$this` 必须是当前文章的 `Widget_Archive`：

```php
<?php if (class_exists('Fediverse_Plugin')): ?>
    <?php Fediverse_Plugin::renderPostInteractions($this); ?>
<?php endif; ?>
```

渲染函数自带作用域限定的通用样式，继承主题颜色和字体，支持移动端、深色模式、键盘焦点、高对比度和减少动态效果。主题可通过 CSS 变量调整：

```css
.fediverse-interactions {
    --fediverse-divider: rgba(127, 127, 127, .28);
    --fediverse-muted-opacity: .62;
    --fediverse-focus: currentColor;
}
```

需要完全自定义 HTML 时，可只读取结构化数据：

```php
<?php
$interactions = class_exists('Fediverse_Plugin')
    ? Fediverse_Plugin::postInteractions((int)$this->cid)
    : array('likes' => 0, 'announces' => 0, 'replies' => 0, 'recent' => array());
?>
```

返回字段：

- `likes`：尚未撤销的远端点赞数量。
- `announces`：尚未撤销的远端转发数量。
- `replies`：已接收且尚未删除或撤销的联邦回复数量，包括待审核回复。
- `recent`：最多 12 条最近点赞或转发，包含 `type`、`actor` 和 `created`。

### 标记联邦回复

在主题 `comments.php` 的单条评论回调中，将以下代码放在评论作者名称之后：

```php
<?php if ((string)$comments->agent === 'ActivityPub'): ?>
    <span class="fediverse-comment-source">联邦宇宙</span>
<?php endif; ?>
```

调用 `renderPostInteractions()` 时已经包含 `.fediverse-comment-source` 的通用样式。若主题只调用 `postInteractions()` 自定义互动区，则需要自行定义该标记样式。

## 安全模型

- 所有入站活动必须带有效的 `Digest`、`Date` 和 HTTP Signature。
- Activity ID 通过数据库唯一键原子去重；入站签名公钥必须出现在对应 Actor 文档中，且密钥 ID 与 owner 都必须匹配。
- 已验签活动会先占用 Activity ID 并写入额度台账，再执行业务副作用；处理异常会保留 `rejected` 状态。
- `Note` 和 `Article` 必须明确归属于 Activity Actor；已有时间轴对象不能被其他 Actor 复用，旧版本或无版本的 `Update` 不能回退时间轴和远端评论。
- 远端 URL 必须使用 HTTPS，且不能包含凭据。
- DNS 解析结果必须全部为公网地址；拒绝私有、保留和回环地址。
- 下载响应限制为 2 MiB，HTTPS 重定向最多 5 次，每一跳重新进行安全校验。
- 入站频率与存储配额按 Actor 和来源域分别统计，超限返回 HTTP `429`。
- 远端回复经过 Typecho `Widget_Feedback:comment` 过滤器，并默认进入待审核状态。
- 头像、Banner 和资料字段不接受原始 HTML；插件不会代理远端媒体。远端账号缓存只接受无凭据的 HTTPS 地址；后台时间轴将头像作为外链而非图片加载，并只显示经过清洗的 HTTPS 媒体链接，避免页面打开时向第三方主机暴露管理员 IP。

## 常见问题

### 远端搜索不到本站账号

先直接检查 WebFinger 和 Actor 地址是否返回 `200`，并确认响应没有 BOM、空白或主题输出。若使用 CDN、反向代理或 `www` 跳转，联邦域名必须与 Actor ID 保持一致。

### 关注一直显示等待确认

检查“管理 → 联邦管理 → 投递队列”是否存在失败任务，再查看入站活动中是否收到 `Accept` 或 `Reject`。确认 Cron 正常运行，并避免裸域名与 `www` 分别生成不同 Actor ID。

### 新文章没有出现在远端

确认远端账号在文章发布前已经成为关注者，并检查投递队列。历史漏投可使用“补发最近文章”，随后立即处理队列或等待 Cron。

### 远端已有回复，但文章只显示数量

远端回复默认进入 Typecho 待审核队列。互动区会计入回复数量，但正文需要在 Typecho 评论后台审核通过后才显示。

### 头像、Banner 或资料字段没有更新

在个人设置中重新保存资料，或在“管理 → 联邦管理”执行“同步作者资料”，然后处理投递队列。远端实例仍可能保留自身缓存，需要等待其刷新。

### 收件箱返回 HTTP 429

表示 Actor 或来源域触发了速率限制或存储配额。先检查入站活动来源和 Cron 清理是否正常，再调整对应全局设置。

## 当前限制

- 匿名 Typecho 评论不会联邦发送；只有具备本地联邦身份的登录用户评论会投递。
- 远端投票目前只展示结果，暂不支持提交投票或从 Typecho 发起投票。
- 暂不接收或发送私信，也不提供 Mastodon 式远端媒体代理或本地媒体缓存。
- 时间轴附件以安全链接和替代文本展示，不直接生成图片、视频或音频预览。
- 安装插件前的旧文章需要重新保存或使用“补发最近文章”才会主动投递。
- 不同 Fediverse 实现对 HTTP Signatures 的细节仍可能存在差异，生产部署应分别使用 Mastodon、Pleroma/Akkoma、GoToSocial 等实例验证。

## 上线检查

1. WebFinger 返回 `application/jrd+json`，Actor 返回 `application/activity+json`。
2. Mastodon 等远端可以搜索完整账号 `@author@example.com`。
3. 远端关注后，本站出现关注者并成功回送 `Accept`。
4. 发布测试文章后，队列成功发送且远端时间线出现文章。
5. 远端回复后，Typecho 后台出现待审核评论，审核通过后文章页显示正文。
6. 文章互动区正确显示点赞、转发和联邦回复数量。
7. “管理 → 联邦管理”没有持续失败或停止重试的任务。
8. Cron 能持续处理队列并清理过期数据。

## 卸载与数据

停用插件会保留联邦数据和作者私钥。需要永久卸载时，先备份数据库，再手工删除名称中包含 `fediverse_` 的插件数据表；删除私钥后无法恢复原有联邦身份。
